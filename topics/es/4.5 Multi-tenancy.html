Funciones principales

Multi-tenancy

ChameleonMap supports un multi-tenant architecture, allowing multiple independent environments, called tenants, para ser managed de un single installation. Each tenant has its own isolated workspace, including its usuarios, datos, y acceso URL.

Tenant management es performed through el ChameleonMap Administrative Portal. Authorized administradores puede crear nuevo tenants, manage tenant usuarios, y view el domains associated con each environment.

Administrative Portal: https://admin.mapa.rnp.br/

Acceso al portal administrativo

Abra el Administrative Portal y authenticate using your administrador credentials. Only usuarios con administrative privileges son authorized para crear y manage tenants.

After authentication, el administrative dashboard es displayed. El sidebar provides acceso para tenant management features.

El following sections son used during tenant administration:

  • Clients - Crear y manage tenants.
  • Domains - View el domains associated con each tenant.
  • Tenant Usuarios - Crear y manage tenant owners y administradores.

Creación de un nuevo tenant

La creación de un tenant consta de dos pasos secuenciales:

  1. Crear el tenant owner.
  2. Crear el tenant, also called un Client.

El tenant owner debe exist before el tenant itself puede ser creado.

Paso 1 - Crear un usuario del tenant

Navigate para:

Clients > Tenant Users

Haga clic el + button para crear un nuevo tenant usuario.

Complete el obligatorio information.

Campo Descripción
Nombre Full nombre de el usuario.
Email Address Email address used para authentication y contraseña setup.

Additional campos may ser configurado according para your organization's requirements. When all obligatorio information has been entered, haga clic Guardar.

Importante: Este usuario será ser selected as el Owner de el tenant during el next step.

Paso 2 - Crear el cliente (tenant)

Navigate para:

Clients > Clients

Haga clic el + button para crear un nuevo tenant.

Fill en all obligatorio campos.

Campo Descripción
Nombre Human-readable nombre de el organization o project.
Tenant Nombre Unique tenant identifier. Este valor es used para automatically generate el tenant's domain.
Schema Nombre Base de datos schema que stores all tenant-specific datos.
Owner Seleccione el Tenant Usuario creado en el previous step.
Tenancy Type Type de tenant. En most deployments, el predeterminado valor, Scoped, debe ser used.

After completing el form, haga clic Guardar. El tenant será ser creado immediately.

Generación automática de dominio

When un Client es creado, ChameleonMap automatically creates un domain para el nuevo tenant.

Para view el generated domain, navigate para:

Clients > Domains

El generated URL puede ser shared con usuarios who debe acceso el tenant. Para example: 

https://wrnp-2026.mapa.rnp.br

No additional configuración es obligatorio after el tenant has been creado.

Primer acceso del usuario

After receiving el tenant URL, usuarios acceso el environment con el email address registered por el administrador. Contraseña creation y contraseña reset son explained en el Primer acceso y restablecimiento de contraseña section.

Flujo de creación del tenant

El following diagram summarizes el tenant creation process.

  1. Administrador logs en Acceso el ChameleonMap Administrative Portal con administrador credentials.
  2. Crear el Tenant Usuario Register el usuario who será ser selected as el tenant owner.
  3. Crear el Client (Tenant) Fill en el tenant information y seleccione el owner creado en el previous step.
  4. Domain es generated ChameleonMap automatically creates el acceso domain para el nuevo tenant.
  5. Share el tenant URL Send el generated URL para el usuarios who debe acceso que environment.
  6. Usuario creates un contraseña El usuario completes first acceso y defines their own contraseña.
  7. Tenant es ready El tenant puede now ser accessed por authorized usuarios.

Solución de problemas

El tenant URL es not disponible

Verify que el Client fue successfully creado y check el Domains página para confirm que el domain has been generated.

El Owner cannot ser selected

Ensure que el Tenant Usuario has been creado y saved before creating el Client.

Un usuario cannot log en

Verify que:

  • el usuario belongs para el correct tenant;
  • el email address es correct;
  • el contraseña has already been creado using el First Acceso o Forgot Contraseña? option.

Notas

  • Only authorized administradores puede crear y manage tenants.
  • Each tenant has its own isolated environment y datos. Usuarios de one tenant cannot acceso datos que belongs para another tenant.
  • Domains son generated automatically during tenant creation.
  • Usuarios authenticate using el URL generated para their tenant.
  • Para security reasons, passwords son configurado por usuarios during their first acceso, so each usuario creates y controls their own contraseña.
