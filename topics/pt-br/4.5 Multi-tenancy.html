Principais funcionalidades

Multi-tenancy

ChameleonMap supports um multi-tenant architecture, allowing multiple independent environments, called tenants, para ser managed de um single installation. Each tenant has its own isolated workspace, including its usuários, dados, e acesso URL.

Tenant management é performed through o ChameleonMap Administrative Portal. Authorized administradores pode criar novo tenants, manage tenant usuários, e view o domains associated com each environment.

Administrative Portal: https://admin.mapa.rnp.br/

Acessando o Portal Administrativo

Abra o Administrative Portal e authenticate using your administrador credentials. Only usuários com administrative privileges são authorized para criar e manage tenants.

After authentication, o administrative dashboard é displayed. O sidebar provides acesso para tenant management features.

O following sections são used during tenant administration:

  • Clients - Criar e manage tenants.
  • Domains - View o domains associated com each tenant.
  • Tenant Usuários - Criar e manage tenant owners e administradores.

Criando um novo tenant

A criação de um tenant consiste em duas etapas sequenciais:

  1. Criar o tenant owner.
  2. Criar o tenant, also called um Client.

O tenant owner deve exist before o tenant itself pode ser criado.

Etapa 1 - Criar um usuário do tenant

Navigate para:

Clients > Tenant Users

Clique o + button para criar um novo tenant usuário.

Complete o obrigatório information.

Campo Descrição
Nome Full nome de o usuário.
Email Address Email address used para authentication e senha setup.

Additional campos may ser configurado according para your organization's requirements. When all obrigatório information has been entered, clique Salvar.

Importante: Este usuário irá ser selected as o Owner de o tenant during o next step.

Etapa 2 - Criar o cliente (tenant)

Navigate para:

Clients > Clients

Clique o + button para criar um novo tenant.

Fill em all obrigatório campos.

Campo Descrição
Nome Human-readable nome de o organization ou project.
Tenant Nome Unique tenant identifier. Este valor é used para automatically generate o tenant's domain.
Schema Nome Banco de dados schema que stores all tenant-specific dados.
Owner Selecione o Tenant Usuário criado em o previous step.
Tenancy Type Type de tenant. Em most deployments, o padrão valor, Scoped, deve ser used.

After completing o form, clique Salvar. O tenant irá ser criado immediately.

Geração automática de domínio

When um Client é criado, ChameleonMap automatically creates um domain para o novo tenant.

Para view o generated domain, navigate para:

Clients > Domains

O generated URL pode ser shared com usuários who deve acesso o tenant. Para example: 

https://wrnp-2026.mapa.rnp.br

No additional configuração é obrigatório after o tenant has been criado.

Primeiro acesso do usuário

After receiving o tenant URL, usuários acesso o environment com o email address registered por o administrador. Senha creation e senha reset são explained em o Primeiro acesso e redefinição de senha section.

Fluxo de criação do tenant

O following diagram summarizes o tenant creation process.

  1. Administrador logs em Acesso o ChameleonMap Administrative Portal com administrador credentials.
  2. Criar o Tenant Usuário Register o usuário who irá ser selected as o tenant owner.
  3. Criar o Client (Tenant) Fill em o tenant information e selecione o owner criado em o previous step.
  4. Domain é generated ChameleonMap automatically creates o acesso domain para o novo tenant.
  5. Share o tenant URL Send o generated URL para o usuários who deve acesso que environment.
  6. Usuário creates um senha O usuário completes first acesso e defines their own senha.
  7. Tenant é ready O tenant pode now ser accessed por authorized usuários.

Solução de problemas

O tenant URL é not disponível

Verify que o Client foi successfully criado e check o Domains página para confirm que o domain has been generated.

O Owner cannot ser selected

Ensure que o Tenant Usuário has been criado e saved before creating o Client.

Um usuário cannot log em

Verify que:

  • o usuário belongs para o correct tenant;
  • o email address é correct;
  • o senha has already been criado using o First Acesso ou Forgot Senha? option.

Observações

  • Only authorized administradores pode criar e manage tenants.
  • Each tenant has its own isolated environment e dados. Usuários de one tenant cannot acesso dados que belongs para another tenant.
  • Domains são generated automatically during tenant creation.
  • Usuários authenticate using o URL generated para their tenant.
  • Para security reasons, passwords são configurado por usuários during their first acesso, so each usuário creates e controls their own senha.
